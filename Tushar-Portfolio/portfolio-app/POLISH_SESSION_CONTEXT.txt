ROOT CAUSE (CONFIRMED):
══════════════════════════════════════════════════════════════════════════════════

The Chibi runtime has TWO texture loading paths:

  PATH A — Document schema `loadMaps` (SceneHost.cjs:2197-2210):
    resolveAsset(asset) → TextureLoader.loadAsync(url) → raw Image as texture
    - Uses Three.js TextureLoader → ImageLoader → new Image()
    - NO canvas rasterisation for SVGs
    - No mapFit support
    - SVGs without explicit width/height attributes render at browser default
      (~150×150 pixels in the Image element)
    - This was the path the old code used (via doc.assets + maps.map)

  PATH B — Runtime `setMaterial` API → `loadOverrideTexture` (SceneHost.cjs:1474-1508):
    new Image() → detects SVG via regex → rasterises to 512×512 canvas
    - Regex: /\.svg(?:[?#]|$)|^data:image\/svg/i
    - SVG_RASTER_SIZE = 512; upscales SVGs to 512px canvas
    - Supports mapFit: "contain" for square decals with aspect ratio preservation
    - Creates CanvasTexture with proper colorSpace (SRGB) and anisotropy (8)
    - This is the RECOMMENDED path per README lines 84-86:
      "author a thin plane child with its own transparent material at opacity: 0,
       then set map + opacity: 1 from the host"

  WHY ICONS WERE INVISIBLE:
    The old code embedded SVG textures via document assets (PATH A). Three.js
    TextureLoader loads the SVGs but creates a small/improper texture. The
    description text SVGs worked because they are data:image/svg+xml URIs with
    explicit width="1024" height="300", giving Three.js a proper-sized Image.
    The icon SVGs only have viewBox="0 0 64 64" with no explicit width/height.

  THE FIX:
    Switch to PATH B — the setMaterial API pattern recommended by Chibi README.
    1. Logo planes are created with opacity:0 and NO embedded texture.
    2. After scene loads, the host calls setMaterial(logoMaterialId, {
         map: iconUrl, mapFit: "contain", opacity: 1
       }) which goes through loadOverrideTexture → 512px canvas rasterisation.

  2. resolveMaterialIds (SceneHost.cjs:1440-1443):
     - `if (doc.materials[target]) return [target]` — direct ID match first
     - Falls back to name match: `Object.values(doc.materials).filter(m => m.name === target)`
     - Our logoMaterialId is a newId("mt") which IS in doc.materials, so ID match works

  3. setMaterialOverride flow (SceneHost.cjs:1518-1537):
     - When patch.map is a URL: does NOT call commit() synchronously
     - Starts async loadOverrideTexture, then commit() in .then()
     - commit() stores scalars + texture in override store, then calls applyOverrides
     - applyOverrides checks host.materials.get(id) — if material not yet created
       by renderer, it's null and overrides are stored but not applied yet

  4. Material creation (SceneHost.cjs:2175-2196):
     - When renderer creates the Three.js material, it calls
       applyOverrides(ctx.overrides, def.id, mat, def.transparent) at line 2192
     - This SHOULD pick up previously stored overrides (both scalars and maps)

  5. API delegation (index.js:253-256):
     - api.current.setMaterial calls materialsRef.current?.set(target, patch)
     - materialsRef is populated by the SceneHost's onMaterials callback
     - This is connected at SceneHost.cjs:963:
       onMaterials?.({ set: (target, patch) => setMaterialOverride(ctx, target, patch) })

  6. SVG RASTERISATION VERIFIED:
     - loadOverrideTexture: SVG_URL regex matches ".svg" in URL
     - SVG_RASTER_SIZE = 512, scales Image to 512px canvas
     - Falls back to naturalWidth||1, naturalHeight||1 for SVGs without dimensions
     - Creates CanvasTexture with SRGBColorSpace, anisotropy=8
